# Lab z/OS 1: Fork the course repository

## Overview

As you work through the lab activities, you will discover "gotchas" or learn additional information, and you will create scripts and JCL files and other artifacts that you may want to keep for future reference. The lab environment is temporary and will not be available after the training is complete. It's useful to make your own copy of the course repository.

## Goals

- Obtain your own copy of the course repository to use as a work space and future reference.

## Prerequisites

1. You have an account on Github or any other service of your choice; or you intend to keep your copy of the repository locally.

## Option 1: Forking is enabled and your destination is on Github

On the landing page for each Github repository, there are a few buttons near the top of the window with labels like Watch, Fork, and Star. Forking may be enabled or disabled at the discretion of the repository's owner. If forking is enabled, you can fork it under your own Github ID by clicking the Fork button. If forking is disabled, use a different method (below) to make a copy of the repository for yourself. 

## Option 2: Forking is disabled or your destination is not on Github 

Clone the course repository on your local system. If you don't intend to store it on a Git service, you're done. If you do want to store it on a git service (Github, Bitbucket, etc.), then create an empty repository on that service, change the remote settings in your local copy, and push to the new repository.
